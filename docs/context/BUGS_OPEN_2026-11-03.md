# Bugs found on the phone, 2026-11-03 (first real use with a bank file and the relay)

Owner reports from the first live test, with the cause found in the code and the fix that was planned. **None of the three below is
fixed in code yet** (the owner stopped work for the day and is rethinking the project); no personal figures here. Each fix needs a test
that reproduces it first (project rule).

## 1. Typed balance is not what the account shows after a Revolut import (money)
- **Symptom:** after "Which account is this?" → new account, the owner typed the balance; the account then showed another number.
- **Cause:** `AccountFormSheet(forImport:)` (`app/lib/src/screens/account_form.dart`) asks for "Balance" and "Balance on", the date
  pre-filled with the day *before the file's first payment*; the hint says the balance is the one *before the first payment*. A balance
  typed from the bank app *now* is stored as the opening balance a day before the first row, then every payment of the file is added on top.
  Nothing overwrites the number (`recordBalanceCheck` / `checkBankBalance` never change a balance).
- **Owner decision:** use the file's own Balance column. Revolut states the balance after every row, so the opening balance can be computed
  exactly and no question is asked.
- **Plan:** core `unknownImportAccounts` fills an optional `StatedStart {openingCents, openingDate, statedCents, statedDate}` per export
  account: `openingCents = stated balance − Σ the group's rows dated up to the stated date`, `openingDate` = the day before the first row;
  null (old behaviour, clearer wording) when the file states no balance (chain unclear, mixed pockets, beyond the cap). The form then hides
  Balance / Balance on and says "The file says the balance is X on D". The post-import check ("matches the bank ✓" / "off by") stays as the
  safety net. Existing accounts are not changed (Settings › Accounts › Correct balance). Tests: Revolut-like batch oldest-first and
  newest-first, same-day rows, last day without a balance, fee row, negative balance, two pockets, cap; app widget test for both forms.
  Agents: `core-builder` + `ui-builder` in parallel, then `reviewer`.
- Also noted, left alone: `BankCheckSheet` pre-fills the app's own computed balance, so a quick tap on "matches" confirms the app's
  number as the bank's. Consider an empty field there.

## 2. Save button hidden behind the Android navigation bar
- **Symptom:** in the Add rule sheet (Needs you → Make rule) Save was half under the phone's 3-button bar and could not be pressed.
- **Cause:** `showSheet` (`app/lib/src/widgets/sheets.dart`, phone branch) pads the bottom by `viewInsets.bottom + 20` only (the keyboard).
  `showModalBottomSheet(useSafeArea: true)` guards top, left and right, not the bottom, and the app draws edge to edge. It affects every
  sheet opened through `showSheet` (the only `showModalBottomSheet` in `lib/`).
- **Plan:** one line: add `MediaQuery.paddingOf(ctx).bottom` to that padding (it is 0 while the keyboard is open, so nothing is counted
  twice). Test first: a 400 × 800 view with a 48 dp bottom padding (`tester.view.padding` / `viewPadding`), a short sheet ending in a
  button; its bottom edge must be ≤ 752 and tappable; plus keyboard-open and dialog-width cases. Then check Add rule and Add expense on the phone.

## 3. "5 things need you" never goes down
- **Symptom:** Needs you always shows 5 items while the owner makes many rules.
- **Cause:** `payeeRecommendations({limit = 5})` (`app/lib/src/controller_suggest.dart`) offers the 5 most frequent payees with no main tag;
  `_needsYouData` makes one card per payee and `needsYouCount()` counts the cards. A rule removes one payee, the next takes its slot.
- **Owner decision:** ONE card with the real total ("N shops have no main tag") that opens a list; each row has Make rule / Dismiss (with
  Undo); "N left" falls as rules are made; the item disappears at 0.
- **Plan:** queue item id `payees` in `controller_needs_you.dart`; new `screens/payee_rules.dart` (`openPayeeRules`, keys `payeeMake:<key>`,
  `payeeDismiss:<key>`); wiring in `screens/needs_you.dart`; raise `payeeCandidates` from 50 to 200 ("200+" when capped) after a perf
  check on the 20k-row wallet; Settings › Tags and rules keeps its 5 for now. Update `test/eng_needs_you_test.dart`, add the cases (12 payees →
  one item; rule → 11 left; dismiss + Undo; empty; cap), 320 dp at text scale 2.0, and the `app/CLAUDE.md` source list. `ui-builder` then `reviewer`.
